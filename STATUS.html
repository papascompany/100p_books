토스 라이브 전환 13단계 (O1)

코드에는 테스트·라이브 분기가 없어 환경변수 2개만 바꾸면 됩니다. 클라이언트 키는 빌드 때 들어가므로 교체 후 재배포가 꼭 필요합니다. 결제위젯 키가 아니라 "API 개별 연동 키"를 씁니다.

  1. 토스 개발자센터에서 라이브 심사가 끝난 100p Books 전용 상점을 선택합니다. 다른 서비스용 상점은 쓰지 않습니다.
  2. 그 상점의 "API 개별 연동 키"에서 라이브 클라이언트 키와 시크릿 키를 확인합니다. 두 키가 같은 상점 것인지 확인합니다.
  3. 전환 전에 관리자 주문 목록에서 테스트 키로 결제된 주문을 확인하고, 있으면 "전액 환불"로 정리합니다.
  4. Vercel 환경변수에서 Production만 TOSS_SECRET_KEY와 NEXT_PUBLIC_TOSS_CLIENT_KEY를 라이브 값으로 바꿉니다. Preview 정책은 따로 정합니다.
  5. Production을 재배포합니다(가능하면 빌드 캐시 없이).
  6. 관리자 런치 체크 카드의 토스 항목이 "정상"인지 봅니다. 이 카드는 키가 있는지만 보므로 라이브 여부는 다음 단계에서 확인합니다.
  7. 토스 웹훅 라이브 탭에 https://<운영 도메인>/api/payments/webhook을 등록합니다.
  8. 관리자에서 1회용 정액 할인 코드를 만들어 결제 금액을 1,000원 안팎으로 맞춥니다.
  9. 실제 카드로 소액 결제합니다. 결제창에 테스트 표시가 없는지, iOS Safari 1건을 포함해 브라우저 오류가 없는지 봅니다.
  10. 결제 완료 화면, 마이페이지 "결제 완료", 토스 상점관리자 결제내역을 확인합니다. 이 주문은 인쇄소로 발주하지 않습니다.
  11. 관리자 주문 상세에서 "전액 환불"을 실행합니다("환불 상태만 기록"이 아님).
  12. 주문이 "환불됨", 토스가 "취소 완료"인지, 할인 코드 사용 횟수가 복원됐는지 확인합니다.
  13. 할인 코드를 비활성화하고 결과를 런북 O1 행에 기록합니다.
도메인 전환 12단계 (O5에서 자체 도메인을 고를 경우)

코드 변경은 없습니다. NEXT_PUBLIC_APP_URL 교체와 재배포로 끝납니다. 도메인을 바꾸면 기존 로그인은 이어지지 않아 고객이 한 번 다시 로그인합니다.

  1. Vercel에 새 도메인을 추가하고 DNS를 등록한 뒤 인증서 발급을 확인합니다.
  2. 새 도메인을 Primary로 지정하고, 기존 vercel.app 주소를 새 도메인으로 308 리다이렉트합니다(발송된 공유·선물 링크 보존).
  3. NEXT_PUBLIC_APP_URL을 새 도메인으로 바꿉니다(끝 슬래시 없이).
  4. Production을 재배포합니다.
  5. Supabase 인증 설정에서 Site URL을 바꾸고, Redirect URLs에 새 도메인 콜백을 추가합니다(전환 기간 기존 항목 유지).
  6. Supabase에 Custom SMTP가 설정돼 있는지 확인합니다(비밀번호 재설정 메일).
  7. 카카오 개발자 콘솔의 Web 사이트 도메인에 새 도메인을 추가합니다.
  8. 토스 웹훅(라이브) URL을 새 도메인으로 바꾸고, 심사 신청서의 사이트 URL과 맞춥니다.
  9. Resend에 새 도메인을 추가하고 SPF·DKIM·DMARC를 등록한 뒤 발신 주소를 설정하고 재배포합니다.
  10. robots.txt, sitemap.xml, 홈의 대표 주소가 새 도메인인지 확인합니다.
  11. 시크릿 창에서 이메일 로그인, 비밀번호 재설정, 카카오 로그인, 선물 링크 복사를 차례로 확인합니다.
  12. 개발 문서와 설정 파일의 도메인 갱신을 CTO에게 요청합니다.
