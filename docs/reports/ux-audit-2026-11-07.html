1. 사용자 주문 플로우 — 마찰 지점과 이번 조치

점선 빨간 테두리 = 점검 시 막히거나 헷갈리던 지점. 초록 배지 = 이번에 수정. 노란 배지 = 구조 개선 제안으로 이월.

2. 영역별 조치 현황

관리자 콘솔 27건 중 약 22건 수정

  • CMS 이미지 업로드가 성공해도 항상 "실패"로 뜨고 반영 안 되던 버그 수정, 실패 토스트 렌더 예외 수정
  • 날짜 필터 KST 기준 — 시작일 00~09시 주문이 빠지던 문제(송장 Excel 누락 위험) 수정, 할인코드 만료를 해당일 23:59로
  • 대시보드 "오늘"·주문 시각을 한국시간으로 표시
  • 모바일 관리자 메뉴 추가(이전엔 메뉴·로그아웃 수단 없음), 활성 메뉴 중복 표시 수정
  • 목록 API 오류를 "결과 없음"으로 보이던 문제 → 오류 문구, 검색은 Enter/버튼 적용·늦은 응답 무시, 필터 변경 시 1페이지
  • 상태 변경 확인창 한국어 라벨, 네트워크 실패 토스트, 영문 라벨(From/To·ON/OFF·감사로그) 한국어화, 본인 계정 관리자 해제 방지

업로드 · 편집 22건 + 실측 3건 중 약 19건 수정

  • 내지 편집 주 버튼이 표지 단계를 건너뛰던 동선 수정
  • 업로드 중·미저장 편집 중 메뉴 이동 시 확인(이전엔 조용히 취소)
  • "요청 실패 (500)" 같은 기술 문구 → 행동 안내 문구, 검증 실패 사진은 재시도 대신 제거
  • 단계 표시 "1/4 · 사진 올리기" 통일, "완성"→"주문 완료", 제목 없는 포토북 표시, 빈 초안은 업로드로
  • 모바일: "자동 편/집" 제목 끊김, 표지 헤더 3줄 → 2줄, 터치기기 편집 배지 상시 표시
  • 스크린리더 과다 알림 정리, 이미지 아닌 파일 드롭 안내

주문 · 결제 · 마이페이지 22건 + 실측 2건 중 15건 수정

  • 배송 조회 불가(송장이 DB엔 있는데 화면에 없음) → 택배사·송장번호·발송/완료일 표시
  • 환불 정책과 화면 불일치 → 결제완료/제작중 상태별 환불 안내 + 고객센터 연결
  • 결제 대기 주문 "결제 계속하기", 결제 완료 화면 주 버튼·요약, 사용자 취소 시 중립 문구
  • 주문서: 편집 복귀 링크, 상품금액 소계, 포인트 최대치 안내, 약관 전체 동의, 입력칸 접근성
  • 내부 정보 노출 제거(결제 키, DB 오류 원문, 상태 enum), 포인트 표기 통일

공통 수정

  • 한국어 어절 단위 줄바꿈(전 화면) — "변환돼/요", "남기세/요", "100/장" 끊김 해소
  • 고객센터 번호 단일 상수화(푸터·주문 안내 공유)

3. 구조 개선 제안 — 효과 × 작업량

원 크기 = 영향받는 사용자 비중. 오른쪽 위로 갈수록 효과 대비 작업량이 작음(먼저 할 것).

#제안왜 필요한가 (점검 근거)효과작업량
P1모바일 주문서 하단 고정 결제바(최종 금액 + 결제 버튼)390px에서 결제 버튼이 긴 폼 맨 아래 — 금액 확인·결제까지 스크롤 4~5화면높음작음
P2표지 모바일 캔버스 높이 맞춤표지 캔버스가 너비 기준으로만 맞춰져 앞표지 하단이 도구막대에 가림(실측)높음작음~중간
P3버튼 터치 타깃 44px 기준(모바일 sm 버튼 h-11)업로드·에디터·포토북 메뉴 버튼 32~40px중간작음
P4표지 규격 사전 판정 — 주문서 진입 시 바로 안내 + 표지 링크규격 바뀐 표지는 입력을 다 마치고 결제 누를 때에야 작은 글씨로 409 안내높음작음
P5결제 전 최종 확인 단계(표지·내지 미리보기 + 3D, 주문서 상단 또는 /review)인쇄물이라 환불 불가인데 주문서에 미리보기가 없음높음중간
P6업로드 직후 자동 페이지 생성, 설정 폼은 "다시 구성"으로 접기 · PDF 다운로드는 주문 후로모바일 첫 화면이 정렬 4 + 레이아웃 2 폼과 인쇄 용어(300dpi·재단선) 카드로 시작높음중간
P7에디터 전용 레이아웃(사이트 헤더·푸터 제거, 캔버스 공간 확대)에디터 sticky 툴바가 사이트 헤더 밑으로 겹치고, 편집 화면 아래 푸터가 붙음높음중간
P8환불 신청 기능 + 배송 타임라인(결제→제작→발송→완료)지금은 고객센터 전화 안내까지만 — 셀프 신청·진행 상황 시각화 없음중간큼
P9선물 기능 의미 결정(편집 사본 공유 vs 실물 배송) — 오너 결정"선물하기"가 실물 배송이 아니라 사본 공유 — 문구로 명시했지만 기대와 다를 수 있음. 수령 페이지 썸네일 미표시·막다른 길도 함께중간중간
P10오류 코드 → 사용자 문구·이동 버튼 매핑 계층(API·클라이언트 공통)화면마다 오류 문구 처리 방식이 달라 내부 정보가 새거나 해결 경로가 없음중간중간
P11관리자 공용 목록 훅·확인 다이얼로그·adminFetch6개 목록 화면이 같은 패턴을 복붙 — 이번 수정도 화면별로 반복 적용중간(운영자)중간
P12관리자 대용량 업로드를 서명 URL 방식으로배경 10MB·폰트 5MB를 함수에 직접 전송 — Vercel 요청 한도(4.5MB) 초과 가능중간(운영자)중간
P13업로드 큐를 레이아웃 수준으로 올려 화면 이동 중에도 업로드 계속이번엔 이탈 확인으로 막았지만, 근본적으로는 이동해도 업로드가 이어지는 편이 자연스러움중간큼
P14CMS 변경 감사 로그 · 할인 코드 수정/사용 내역콘텐츠 저장은 감사 로그에 안 남고, 할인 "내역" 버튼은 빈 목록낮음작음~중간
P15주문 상세 금액 내역 공용 컴포넌트(주문서·완료·상세 동일 표기)상세 화면은 할인·포인트·결제액만 있어 합계가 맞아떨어지지 않음낮음작음

5. 점검 방법과 한계

  • 코드 감사 3건(관리자 / 업로드·편집 / 주문·결제) + 실제 화면 촬영: 임시 테스트 계정으로 로그인해 업로드→내지→표지→주문서까지 데스크톱·390px 모바일 22장 캡처(결제창은 열지 않음, 테스트 데이터 자동 정리).
  • 관리자 화면은 실제 고객 주문·개인정보가 보이므로 캡처하지 않고 코드로만 점검.
  • 토스 결제창 이후(결제 완료·실패·주문 상세의 배송 정보)는 실결제 없이 코드로 확인 — 실제 주문 데이터로 화면 확인은 오픈 후 첫 주문 때 권장.
