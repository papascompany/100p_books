다음 개발 이슈 — 오픈 전 처리 (CTO)

UX 점검에서 남은 15건 중 오픈 전에 고객·운영자가 바로 부딪히는 3건(P10·P12·P15)과, 편집물·인쇄 품질 관련 확인 작업을 골랐습니다. 큰 작업(P8·P13)은 오픈 후로 미룹니다.

#작업왜 오픈 전에작업량일정
D1주문 금액 내역 공용 컴포넌트 (UX P15)주문 상세에는 할인·포인트·결제액만 있어 합계가 맞지 않습니다. 첫 고객의 금액 문의를 줄입니다.작음11/11
D2오류 코드 → 사용자 문구·이동 버튼 매핑 (UX P10)화면마다 오류 처리 방식이 달라 내부 코드가 보이거나 다음 행동이 없는 화면이 있습니다.중간11/11~12
D3관리자 리소스 업로드를 서명 URL 방식으로 (UX P12)지금은 파일이 서버 함수를 거쳐 Vercel 한도 4.5MB를 넘으면 실패합니다. 배경 이미지 한도는 10MB라 클립아트·배경을 채우기 전에 고쳐야 합니다.중간11/12~13
D4여러 개 선택 중 자동저장 좌표 재현·수정선택 그룹 기준의 상대 좌표로 저장될 수 있다는 추정이 남아 있습니다. 사실이면 인쇄물 배치가 어긋납니다.작음~중간11/12
D5PDF 콜라주 6컷 메모리 x64 실측측정은 로컬 arm64에서만 했습니다. 운영과 같은 Linux x64에서 100페이지 메모리를 확정합니다.작음11/13
D6내 포토북 카드 썸네일·"Untitled" 제목 · 표지 저장 중복 요청첫 사용자가 보는 목록이 아이콘과 Untitled로만 채워집니다.작음11/13
D7카카오 로그인 실제 왕복 1회 확인라이브러리 업그레이드 후 OAuth 콜백은 자동 테스트로 검증되지 않았습니다(O6 이후).확인11/17
D8iOS Safari 실기기 핀치·더블탭 확인편집 제스처 QA는 Chromium 에뮬레이션으로만 했습니다.확인11/18

오너 액션 — 마감일 순

#할 일늦어지면구분마감
O5운영 도메인 결정 — 100pbooks.vercel.app 유지 또는 자체 도메인카카오 Redirect·Resend 발신 도메인·토스 웹훅 주소가 모두 이 값에 묶여 다시 등록해야 합니다.필수11/12
O4Upstash Redis 연결 (Vercel 마켓플레이스, 5분)가입·업로드 남용 제한이 꺼진 채로 오픈합니다.필수11/12
O1토스 라이브 계약·심사 신청 → 라이브 키를 Vercel에 반영 → 웹훅을 라이브 단계에 재등록실결제가 불가능해 오픈할 수 없습니다.크리티컬신청 11/11
키 11/16
O2실물 테스트 인쇄 1부 발주 — 인쇄소 수동 발주 절차 확정, 글자 굵기(canvas 1.1 판단) 확인첫 주문 품질을 오픈 후에야 알게 됩니다.크리티컬발주 11/13
수령 11/18
O7Storige 통지 붙여넣기 1회 (docs/STORIGE-NOTICE.md)Storige가 스토리지를 옮기면 업로드가 예고 없이 막힐 수 있습니다.필수11/13
O3Resend 키 + 발신 도메인 DNS(SPF·DKIM·DMARC)주문 확인·배송 메일이 큐에 쌓이기만 합니다(키 등록 시 일괄 발송).필수11/14
O6카카오 개발자 콘솔 + Supabase 설정카카오 버튼이 숨겨진 채 이메일 가입만으로 오픈합니다.선택11/14
O9클립아트·배경 리소스 업로드 (D3 이후)편집 팔레트가 "표시할 리소스가 없어요"로 보입니다.선택11/17
O8랜딩 수치·후기 문구 재확인11/6 "현행 유지"로 결정했지만, 오픈부터는 "5,000+ 제작·4.9★"가 실제 고객에게 보입니다(실제 주문 0·후기 0). 표시광고 관점에서 마지막으로 확인해 주세요.권고11/19

11/18 GO/NO-GO 기준

  • 라이브 키가 반영되고 실결제 소액 1건 → 관리자 "전액 환불"이 정상 처리됨
  • 실물 인쇄물 품질 합격(글자 굵기·재단선·색)
  • 전체 회귀 통과: typecheck·lint·test·PDF 회귀·build·운영 E2E·접근성·인증 E2E
  • 관리자 "서비스 런치 체크" 카드 차단 항목 0

하나라도 실패하면 오픈일을 다시 잡습니다.
